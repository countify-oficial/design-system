# Botões

Botões disparam uma ação: salvar, abrir, enviar, filtrar. A Countify tem uma família de botões que dividem a
mesma base (`UnstyledButton`): foco visível pelo teclado, `disabled` que funciona também em links e as medidas dos
tokens (alvo de toque de 44 px no mínimo).

Esta página é o manual de uso. Cada componente tem também a sua página própria, com os controles para mexer nas props.
Os exemplos seguem o modo claro ou escuro escolhido em **Modo**, na barra de cima.

## Visão geral

Todos os botões da biblioteca, lado a lado. Todos funcionam: clique, use o Tab e as setas.

## Instalação

```bash
pnpm add @countify-oficial/core @countify-oficial/provider @countify-oficial/tokens
```

Carregue os estilos uma vez, na entrada do app, e envolva o app no `CountifyProvider`:

```tsx
import "@countify-oficial/tokens/fonts.css";
import "@countify-oficial/tokens/tokens.css";
import "@countify-oficial/core/styles.css";
import { CountifyProvider } from "@countify-oficial/provider";

createRoot(document.getElementById("root")!).render(
  <CountifyProvider defaultColorScheme="auto">
    <App />
  </CountifyProvider>,
);
```

`variant` muda o peso visual (`filled`, `outline`, `subtle`, `dashed`); `color` muda o significado: `accent` (padrão),
`down` (queda, exclusão), `up` (alta, sucesso) e `warn` (aviso).

  }}
/>

### Como link

Com `component`, o botão vira outro elemento e aceita as props dele. Para navegar, use um link (`a`, ou o `Link` do seu
roteador), não um `onClick` com `navigate()`: assim o usuário pode abrir em outra aba.

<Canvas

{/* com o React Router */}

  }}
/>

## ActionIcon

Botão só com ícone. O `aria-label` é **obrigatório** (o TypeScript cobra): sem ele, o leitor de tela anuncia só
"botão". Se o sentido do ícone não for óbvio, ponha também um `Tooltip`.

```tsx
import { ActionIcon, Icon } from "@countify-oficial/core";

<ActionIcon aria-label="Editar painel" onClick={editar}>
  <Icon name="edit" />
</ActionIcon>
```

### Variantes

`subtle` (padrão, sem fundo, como o Voltar), `default` (cartão com anel, como o Editar) e `filled` (fundo de chip).

## CopyButton

Não desenha nada: copia `value` e avisa por um tempo (`timeout`, padrão 2 s) que copiou. O botão é você quem
escolhe, pela função filha. Na web, a área de transferência só funciona em página segura (https ou localhost).

<Canvas
  of={CopyButtonStories.Padrao}
  source={{
    language: "tsx",
    code: `import { Button, CopyButton, Icon } from "@countify-oficial/core";

<CopyButton value="K7Q-29XM">
  {({ copied, copy }) => (
    <Button
      variant="outline"
      onClick={copy}
      leftSection={<Icon name={copied ? "check" : "key"} size="sm" />}
    >
      {copied ? "Código copiado" : "Copiar código"}
    </Button>
  )}
</CopyButton>`,
  }}
/>

Com um `ActionIcon`, troque também o nome para o leitor de tela:

```tsx

  {({ copied, copy }) => (
    <ActionIcon aria-label={copied ? "Link copiado" : "Copiar link"} onClick={copy}>
      <Icon name={copied ? "check" : "copy"} />
    </ActionIcon>
  )}
</CopyButton>
```

## Personalizar

### Padrões para o app inteiro

Pelo tema do `CountifyProvider`, sem repetir a prop em cada botão:

```tsx
import { CountifyProvider, createTheme } from "@countify-oficial/provider";

const theme = createTheme({
  components: {
    Button: { defaultProps: { size: "sm", radius: "md" } },
    ActionIcon: { defaultProps: { variant: "default" } },
  },
});

<CountifyProvider theme={theme}>
  <App />
</CountifyProvider>;
```

### Partes internas

`classNames` e `styles` chegam em cada parte do componente. No `Button`, as partes são `root`, `label`, `section` e
`loader`; nos outros, `root`.

```tsx
<Button
  classNames={{ label: classes.rotulo }}
  styles={{ section: { color: "var(--cf-color-up)" } }}
>
  Salvar
</Button>
```

Prefira as props (`variant`, `color`, `size`) a CSS próprio: elas já seguem os tokens nos dois modos, claro e escuro.

## Texto do botão

- Comece com um verbo e diga o que acontece: "Salvar", "Imprimir etiquetas", "Excluir análise".
- Curto: de uma a três palavras. A explicação vai no texto em volta, não no botão.
- O mesmo verbo do título: se a janela é "Excluir análise?", o botão é "Excluir", não "Sim".
- Enquanto carrega, o gerúndio do mesmo verbo: "Salvar" vira "Salvando".
- Sem ponto final, sem caixa alta no texto todo.

## Acessibilidade

- Todo botão é um `<button type="button">` de verdade, ou o elemento de `component` com o comportamento certo.
- Foco visível pelo teclado em todos.
- `ActionIcon` exige `aria-label`; `CloseButton` e `Burger` já trazem o nome.
- `loading` marca `aria-busy`; `Toggle` marca `aria-pressed`; `Burger` marca `aria-expanded`.
- Alvo de toque de 44 px no mínimo, mesmo no tamanho `xs`.

    <tr><td><kbd>Enter</kbd></td><td><code>Button component="a"</code></td><td>Segue o link (o Espaço não, como em qualquer link).</td></tr>
    <tr><td><kbd>←</kbd> <kbd>→</kbd></td><td><code>Toolbar</code></td><td>Anda entre os botões da barra (<kbd>↑</kbd> <kbd>↓</kbd> na vertical).</td></tr>
    <tr><td><kbd>Home</kbd> / <kbd>End</kbd></td><td><code>Toolbar</code></td><td>Vai para o primeiro / o último botão da barra.</td></tr>

## Faça e não faça

<table>
  <thead><tr><th>Faça</th><th>Não faça</th></tr></thead>
  <tbody>
    <tr><td>Um <code>filled</code> por tela, para a ação principal</td><td>Vários <code>filled</code> competindo lado a lado</td></tr>
    <tr><td>Verbo no texto: "Salvar", "Excluir análise"</td><td>"OK", "Sim", "Clique aqui"</td></tr>
    <tr><td><code>color="down"</code> e confirmação para excluir</td><td>Excluir sem perguntar, ou com <code>filled</code> vermelho no meio das outras ações</td></tr>
    <tr><td><code>component="a"</code> (ou <code>Link</code>) para navegar</td><td><code>{"onClick={() => navigate(...)}"}</code> num botão</td></tr>
    <tr><td><code>loading</code> enquanto espera a resposta</td><td>Trocar o botão por um girador solto</td></tr>
    <tr><td><code>aria-label</code> que diz a ação ("Editar painel")</td><td><code>aria-label</code> que descreve o ícone ("Lápis")</td></tr>
  </tbody>
</table>
